# 迁移与开源范围

目标是在保留现有离线功能的前提下，让模型服务由本项目直接维护，
并把代码、安装步骤、依赖和测试记录整理成别人能够复现的仓库。

### 当前已完成的准备

1. 单独建立候选目录，不在旧工程上直接覆盖。
2. 根据板上已确认的 RKLLM 1.3.0 设计 C++ 适配层。
3. 编写本地模型配置、模板分词、模型生命周期和兼容 HTTP 接口。
4. 增加模型切换、断开取消、流式结束及错误处理测试。
5. 提供板端准备、依赖检查和源码打包工具。
6. 实机通过 Qwen → DeepSeek → Qwen 三次流式问答、模型卸载及旧后端恢复。
7. 通过现有网页代理和语音流式客户端调用新后端；SenseVoice、VITS 及 PCM 播放软件链路通过。
8. 完成仅修改模型启动分支的安装与回退工具，原生界面仍使用既有入口。
9. 实机验证生成中取消及下一次问答；正常重启后的模型服务、网页和桌面待唤醒恢复通过。
10. 已迁入在用界面、网页、语音和原厂启动桥接的源码快照，记录逐文件哈希及运行依赖，提供兼容路径说明。

### 还未完成

- 完成空白系统的安装自动化与回归；当前提供的是已运行源码快照和已经实测的既有部署迁移工具。
- 录制或整理不含私人对话的展示材料，补充完整安装教程。
- 完善发行与适配自动化；当前维护仓库为 zjinw520/rk3588-offline-assistant。

安装工具可将现有部署切换到独立后端；未安装的用户仍使用自己的原后端。
已确认本板的 NPU 推理成功，不将其扩展为所有板卡、所有模型或所有驱动版本均兼容。
完整开源版也仍依赖官方运行库和第三方模型。

### 稳定版本的保留方法

现有目录、模型、虚拟环境和原厂桌面保留以便回退；迁移安装器仅替换模型服务启动分支。
本轮新包只解压到 /userdata/local-ai-candidate-v010。
如果候选检查失败，停止操作并保留输出，原服务可照常使用。
后续切换前需记录旧后端的进程身份及子进程，确认 NPU 资源已释放，
再由新服务占用 8080；不能仅按 PID 文件或 killall python 处理。
回退应恢复确切的原启动方式，不依赖删除模型或重刷系统。

### 性能预期

移除 RKLLama 是为了掌握服务实现和简化依赖，不保证模型会更聪明或回答更快。
同一个 DeepSeek 推理模型仍可能输出很长的思考内容。
当前主要性能收益仍应来自选用适合语音交互的模型、减少输出长度、
分段合成播放及避免重复加载；后续以板端测量作比较。
